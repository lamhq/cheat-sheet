# Kafka

## Introduction

Apache Kafka is a distributed publish-subscribe messaging system and a robust queue.

It can handle a high volume of data and enables you to pass messages from one end-point to another.

Kafka is very fast and guarantees zero downtime and zero data loss.

Messages are stored for a period of time before deleted.

Messages are replicated within the cluster to prevent data loss.

## Advantages

- **Performance**. Kafka can handle a lot of data quickly (can process 100+ events / sec). It maintains stable performance even many TB of messages are stored.
- **Reliability**. Kafka is distributed, partitioned, replicated and fault tolerance.
- **Scalability**. Kafka messaging system scales easily without down time..
- **Durability**. Kafka uses Distributed commit log which means messages persists on disk as fast as possible, hence it is durable..


## Kafka APIs

**Data Ingestion (Source → Kafka):**
- **Kafka Connect Source:** Use when data already exists in a source system (database, etc.) and you want to ingest it into Kafka
- **Kafka Producer:** Use when data originates directly from your application (e.g., truck GPS data) and you want to send it straight to Kafka as the source of truth

**Data Transformation (Kafka → Kafka):**
- **Kafka Streams:** A library for processing and transforming data within Kafka topics in real-time
- **KSQL DB:** A database layer that allows SQL queries on Kafka topics (internally uses Kafka Streams)

**Data Export (Kafka → Target System):**
- **Kafka Connect Sink:** Use when you want to store processed data in external systems (databases, data warehouses) for storage and analysis
- **Kafka Consumer:** Use for lightweight, one-off tasks (e.g., sending emails) where data doesn't need to be persisted

**Data Validation:**
- **Schema Registry:** Ensure data types and schemas remain consistent and accurate across all pipelines
