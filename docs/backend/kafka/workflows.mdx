# Workflows

Kafka supports both pub-sub and queue-based messaging.

Producers send messages to a topic; consumers choose their messaging pattern based on need.

## Pub-Sub Messaging

- Producers send messages to a topic
- Brokers store messages across partitions
- Consumers subscribe and receive the current offset
- Consumers poll periodically for new messages
- Kafka forwards messages for processing
- On acknowledgment, Kafka updates the offset
- Consumers can rewind or skip to any offset at any time

## Queue Messaging

- Producers send messages to a topic
- Brokers store messages across partitions
- Consumers subscribe with a **Group ID**
- Kafka distributes messages across consumers in the group until consumer count equals partition count
- Extra consumers remain idle until a partition frees up
- This creates load balancing across the consumer group
