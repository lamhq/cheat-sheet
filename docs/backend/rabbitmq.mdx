# RabbitMQ

This document is for version 4.2.2.

## Introduction

RabbitMQ is an open-source message broker that facilitates communication between application components by sending and receiving messages.

RabbitMQ is based on AMQP protocol.

:::info
AMQP is an open standard protocol that defines how messages are formatted, stored, routed, and delivered between systems.
:::


## Use cases

- Message queuing and pub/sub messaging
- Background task scheduling
- Load distribution across multiple servers
- Seamless component integration in distributed systems


## Erlang

RabbitMQ is written in Erlang, a language designed for concurrency, fault tolerance, and distributed systems.

It uses lightweight Erlang processes to handle thousands of simultaneous connections.


## Comparison

| Feature | RabbitMQ | Kafka | Kinesis |
|---------|----------|-------|---------|
| Open Source | Yes | Yes | No |
| Message Removal | After consumption | Stored | Stored |
| Throughput | Good | Higher | Higher |
| Cost | Low | Low | High (AWS) |
| Best For | Task queues, routing | Event sourcing, streams | AWS analytics |

**Key Difference**: RabbitMQ uses push model (sends to consumers), while Kafka uses pull model (consumers fetch).


## Running

You can run RabbitMQ using Docker for local development:

```sh
docker run -it --rm --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:4-management
```
