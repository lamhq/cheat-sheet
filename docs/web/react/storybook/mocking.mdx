# Mocking

## Mock modules

There are **two** approaches to mocking modules, they both require creating a mock file to replace the original module. The difference is how you import the mock file into your component.

Limitations:
- Relative imports are not supported. You have to use absolute import.
- Not flexible per story. This method applies globally, so you can't easily swap out different mocks for different stories.

Conclusion: the cost for mocking modules like this is not acceptable. So i choose to avoid mocking in Storybook.


## Mock network requests

Install MSW and the MSW addon:

<PackageManagerTabs command="install -D msw msw-storybook-addon" />

Generate service worker file for MSW to work:

```sh
npx msw init public/
```

Include the generated service worker file in your Storybook configuration:

```ts title=".storybook/main.ts"
// ...

const config: StorybookConfig = {
  // ...
  staticDirs: ['../public'],
};

export default config;
```

Initialize the addon and apply it to all stories:

```ts title=".storybook/preview.tsx"
// ...
import { initialize, mswDecorator } from 'msw-storybook-addon';
import { handlers } from '../src/msw/handlers';

// Initialize Mock Service Worker
initialize({
  onUnhandledRequest: 'bypass', // or 'warn' or 'error'
});

const preview: Preview = {
  // ...
  parameters: {
    // ...
    msw: { handlers },
  },
  loaders: [mswLoader],
};

export default preview;
```

The global `msw` handlers:

```ts title="src/msw/handlers.ts"
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.get('/api/posts/:id', async ({ params }) => {
    const { id } = params;
    return HttpResponse.json({
      id: id,
      title: 'Demo Post',
      content: 'Lorem ipsum dolor sit amet consectetur adipiscing',
      tags: ['play', 'gog'],
    });
  }),
];
```

To mock HTTP requests in stories:

```ts
import { http, HttpResponse, delay } from 'msw';

export const MockedSuccess: Story = {
  parameters: {
    msw: {
      handlers: [
        http.get('https://your-restful-endpoint', async () => {
          await delay(800);
          return new HttpResponse(null, {
            status: 403,
          });
        }),
      ],
    },
  },
};
```

Instead of defining `parameters.msw` in each story, it can also be configured at the `component` or even `project` level, allowing you to share the same mock server configuration across multiple stories.


## Mock context value

For components that receive data from context defined in higher component tree, you can wrap your component in a `decorator` that includes the necessary context.

```tsx title=".storybook/preview.ts"
import React from 'react';

// Replace your-framework with the framework you are using, e.g. react-vite, nextjs, nextjs-vite, etc.
import type { Preview } from '@storybook/your-framework';

import { ThemeProvider } from 'styled-components';

const preview: Preview = {
  decorators: [
    (Story, { parameters }) => {
      const { theme = 'light' } = parameters; // [!code highlight]
      return ( // [!code highlight]
        <ThemeProvider theme={theme}> // [!code highlight]
          <Story /> // [!code highlight]
        </ThemeProvider>
      );
    },
  ],
};

export default preview;
```

```tsx title="Button.stories.ts"
// Replace your-framework with the framework you are using, e.g. react-vite, nextjs, nextjs-vite, etc.
import type { Meta, StoryObj } from '@storybook/your-framework';

import { Button } from './Button';

const meta = {
  component: Button,
} satisfies Meta<typeof Button>;
export default meta;

type Story = StoryObj<typeof meta>;

// Wrapped in light theme
export const Default: Story = {};

// Wrapped in dark theme
export const Dark: Story = {
  parameters: {
    theme: 'dark',
  },
};
```
