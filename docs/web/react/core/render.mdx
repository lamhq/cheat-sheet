# Render Logic

## Logic inside a component

There are two kinds of logic in a component:

### Rendering code

This is where props and state are transformed into JSX.

It must be pure:
- no mutation of existing variables or objects 
- same input, same output (JSX)

### Event handlers

These are functions that do actions instead of just calculating values:

- update an input field
- send an HTTP request
- navigate to another screen

Event handlers contain **[side effects](./effect.mdx)**.


## UI tree

React organizes components into a tree of parent-child relationships. 

This helps React know what to render and how updates flow through the app.


## Virtual DOM

The virtual DOM is a lightweight in-memory version of the real DOM.

React compares the previous and next versions, then updates only the changed parts in the browser DOM.


## Render process

React renders in three steps:

1. Trigger a render
2. Render the component
3. Commit to the DOM

### Trigger a render

A render happens when:

- the component first mounts
- state or props change and cause an update

```js
import Image from './Image.js';
import { createRoot } from 'react-dom/client';

const root = createRoot(document.getElementById('root'));
// first render
root.render(<Image />);
```

### Render components

React calls your component function to produce JSX.

- On the initial render, it starts at the root component.
- On updates, it re-runs the relevant component(s) and produces a new JSX snapshot.

### Commit changes to the DOM

After rendering, React updates the real DOM. Then the browser repaints the screen.

- On the initial render, it inserts the created DOM nodes into the page.
- On re-renders, it applies only the minimal changes needed (to the DOM) to match the latest output.


## Component lifecycle

1. **Mount** — added to the screen
2. **Update** — receives new props or state
3. **Unmount** — removed from the screen


## Rendering Lists

When rendering arrays, give each item a unique `key`.

- keys must be unique among siblings
- keys must stay stable; avoid generating keys like `key={Math.random()}`

```jsx
const listItems = people.map(person => (
  <li key={person.id}>
    <img src={getImageUrl(person)} alt={person.name} />
    <p>{person.name}: {person.profession}</p>
  </li>
));
```

:::note
Keys help React match items across updates, especially when items are reordered or removed.
:::
