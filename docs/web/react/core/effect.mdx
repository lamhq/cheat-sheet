# Effect

## Side Effects

Side effects are actions that affect something outside the render flow of a component, such as:

- starting animations
- fetching data
- subscribing to events
- updating timers
- writing to local storage
- logging or analytics

Side effects should be in event handlers. If no suitable handler exists, use `useEffect` to run the side effect after rendering.


## Effect (`useEffect`)

Use `useEffect` to run code after rendering to synchronize with something outside React.

Effects are an escape hatch, not the default solution.


## Effect Dependencies

```jsx
import { useEffect } from 'react';

function Example() {
  useEffect(() => {
    const timer = setInterval(() => {
      console.log('tick');
    }, 1000);

    return () => clearInterval(timer);
  // [!code highlight]
  }, []);

  return <div>Example</div>;
}
```

**How it works**:
- No dependency array: runs after every render.
- `[]`: runs once after mount.
- `[a, b]`: runs after mount and whenever `a` or `b` change.

**Rules**:
- Include every reactive value used inside the effect.
- If a value is non-reactive, extract it into an **effect event** when needed.
- Avoid objects/functions as dependencies. They are recreated on each render, and can trigger unnecessary re-runs.


## Cleanup Function

Return a cleanup function to undo the effect.

It will run:
- When the component is about to unmount.
- Before the effect runs again on a subsequent render

```js
useEffect(() => {
  const connection = createConnection();
  connection.connect();
  return () => {
    connection.disconnect();
  };
}, []);
```


## Development mode

In development, React intentionally mounts, unmounts, and remounts components once to help you verify cleanup logic (`useEffect` is called twice).


## When to use?

1. [Controlling non-React widgets](https://react.dev/learn/synchronizing-with-effects#controlling-non-react-widgets) (map, modal, video player, etc)
2. [Subscribing to events](https://react.dev/learn/synchronizing-with-effects#subscribing-to-events) (scroll, resize, etc)
3. [Triggering animations](https://react.dev/learn/synchronizing-with-effects#triggering-animations) (fade in, slide down, etc)
4. [Fetching data](https://react.dev/learn/synchronizing-with-effects#fetching-data) (API, database, etc)
5. [Sending analytics](https://react.dev/learn/synchronizing-with-effects#sending-analytics) (Google Analytics, Mixpanel, etc)

## When not to use?

If there is no external system involved, you shouldn't need an Effect:

1. [Initializing the application](https://react.dev/learn/synchronizing-with-effects#not-an-effect-initializing-the-application). You can put it outside your components
2. [Handling user events](https://react.dev/learn/synchronizing-with-effects#not-an-effect-buying-a-product). This should go to event handlers
3. [Updating state based on props or state](https://react.dev/learn/you-might-not-need-an-effect#updating-state-based-on-props-or-state). Just calculate it during rendering.


## useEffectEvent

Use this when a value should not trigger a re-run of the effect.

```jsx
import { useEffect, useEffectEvent } from 'react';
import { createConnection } from './chat.js';
import { showNotification } from './notifications.js';

function ChatRoom({ roomId, muted }) {
  const onConnected = useEffectEvent((roomId) => {
    if (!muted) {
      showNotification('Connected to ' + roomId);
    }
  });

  useEffect(() => {
    const connection = createConnection(roomId);
    connection.on('connected', () => {
      onConnected(roomId);
    });
    connection.connect();
    return () => {
      connection.disconnect();
    }
  }, [roomId]);

  return <h1>Welcome to the {roomId} room!</h1>;
}
```

- `onConnected` is an Effect Event, `muted` and `onConnected` are not in the Effect dependencies.

Limitations:
- Only call Effect Event from inside Effects.
- Never pass them to other components or Hooks.

:::caution
Don't use Effect Events to skip dependencies.
:::
