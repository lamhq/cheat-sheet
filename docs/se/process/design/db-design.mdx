# Database Design Document

Guide for writing Database Design Documents.

## Introduction

A Database Design Document formally describes the schema, relationships, and implementation details of a system or module's database.

## Document Structure

The document typically includes the following sections:

### Introduction

- **Purpose**: to describe the database schema of a system/module.

### ER Diagram

- Provide a logical Entity–Relationship (ER) diagram.
- Show entities, attributes, relationships, and cardinality.

For each table or collection, provide the following details:

### [Table/collection name]

- **Description**: Summarize the purpose of each table (SQL) or collection (NoSQL).
- **Schema Definition**: Show a table with:
  - Column/field name
  - Description
  - DBMS‑specific data types
  - Constraints (PK, FK, unique, etc.)
- **Relationships:** Document relationships with other tables/collections, including type (one‑to‑many, many‑to‑many) and cardinality.
- **Indexes**: Define indexing strategies for query optimization.
- **Storage Details**: Note partitioning, sharding, clustering, or DBMS‑specific features.

### Scripts

- Include SQL or code snippets to create the schema.
- Provide seed scripts for populating initial data.

### Changelog
- Version history of the document.
- Notes on added, deprecated, or removed entities, attributes, or relationships.
